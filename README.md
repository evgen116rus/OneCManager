# OneCManager

Программа для Windows (C++/WinAPI, один exe, без установки и сторонних библиотек) для удалённого обнаружения, удаления и установки версий **1С:Предприятие** на компьютерах в сети.

## Функции

1. **Ввод имени компьютера.** Имя или IP удалённого ПК вводится в окне программы.
2. **Обнаружение версий 1С.** Находит все установленные версии 1С:Предприятие (x64 и x86) и показывает список: название, версия, разрядность, код продукта `{GUID}`.
3. **Удаление выбранных версий.** Напротив каждой версии стоит галочка. Кнопка «Удалить отмеченные» удаляет отмеченные версии (`msiexec /x {GUID} /qn /norestart`) после подтверждения, затем список обновляется. Кнопка «Отметить все» отмечает или снимает все галочки.
4. **Установка новых версий.** Путь к установщику вводится вручную: `.msi`, `.exe` или папка с дистрибутивом (в папке ищется `1CEnterprise 8.msi`, затем любой `.msi`, затем `setup.exe`). Путь может быть сетевым (UNC). Параметры установки редактируются в поле «Параметры».
5. **Выбор способа удалённого запуска.**
   - *Авто*: сначала стандартные средства (WMI + `msiexec` на удалённом ПК), при отказе `pse.exe -r ps_1C`.
   - *Только стандартные средства* (WMI + `msiexec`).
   - *Только `pse.exe -r ps_1C`* (переименованный psexec).
6. **Журнал операций.** Все шаги и результаты (коды возврата, ошибки) выводятся в окно журнала.

## Как это работает

**Поиск версий.** Программа подключается к удалённому реестру и читает ветки `Uninstall` (64- и 32-разрядную). Подходят записи, в названии которых есть «1С/1C» и «Предприятие/Enterprise» (в том числе с кириллической «С»).
Перед чтением реестра на целевом ПК служба **«Удалённый реестр»** переводится в тип запуска «Автоматически» и запускается. Если реестр недоступен, список получается через `pse.exe` и PowerShell.

**Удаление и установка.** Стандартный способ: через WMI (`Win32_Process.Create`) на удалённом ПК запускается `msiexec`, программа ждёт его завершения и читает код возврата. Запасной способ: `pse.exe \\ПК -r ps_1C -s msiexec ...`.

**Копирование дистрибутива.** По умолчанию включена галочка «Копировать дистрибутив на ПК»: папка с установщиком копируется через robocopy в `C:\Windows\Temp\1C_Setup` на целевом ПК (через административный ресурс `C$`), установка идёт локально, после неё папка удаляется. Это обходит проблему «двойного перехода» (удалённый процесс не может открыть сетевую шару). Без галочки `msiexec` читает установщик по указанному UNC-пути, поэтому к нему нужен доступ.

**Параметры установки.** По умолчанию:

```
/qn /norestart TRANSFORMS=adminstallrelogon.mst;1049.mst DESIGNERALLCLIENTS=1 THICKCLIENT=1 THINCLIENTFILE=1 THINCLIENT=1 WEBSERVEREXT=0 SERVER=0 CONFREPOSSERVER=0 CONVERTER77=0 SERVERCLIENT=0 LANGUAGES=RU
```

Измените набор под свою схему (компоненты, язык, трансформации). Для `.exe`-установщика содержимое поля передаётся как аргументы exe.

**Результат.** Код 0: успех. 3010 и 1641: успех, нужна перезагрузка. Остальные коды: ошибка. Подробный лог `msiexec` лежит на целевом ПК: `C:\Windows\Temp\1c_ps.log`.

## Требования

- Windows, запуск от учётной записи с правами администратора на целевом ПК (например, доменный администратор).
- На целевом ПК: доступны RPC/WMI (DCOM) и административный ресурс `C$` (разрешения в брандмауэре).
- `pse.exe` лежит рядом с программой или в PATH. Нужен только для запасного способа и режима «Только pse.exe».
- Для работы программы на локальной машине дополнительные компоненты не нужны.

## Ограничения

- Удаляются только MSI-пакеты (с кодом продукта `{GUID}`). Остальные записи программа пропускает.
- Работа идёт с одним компьютером за раз.
- Если у целевого ПК закрыт RPC или нет доступа к `C$`, потребуется запасной способ через `pse.exe`, который тоже использует административные ресурсы.

## Сборка релиза через GitHub (браузер или Android)

1. Создайте репозиторий на github.com.
2. Добавьте `main.cpp` в корень: **Add file → Create new file**, имя `main.cpp`, вставьте код, **Commit**.
3. Добавьте файл `.github/workflows/build.yml` (слэши в имени сами создадут папки), вставьте содержимое workflow, **Commit**.
4. **Actions → Build and release → Run workflow**, введите версию (например `1.0.0`). В приложении GitHub для Android: репозиторий → Actions → workflow → Run workflow.
5. Через 1-2 минуты в **Releases** появится релиз `v1.0.0` с файлом `OneCManager.exe`.

Релиз также собирается автоматически при создании тега вида `v1.0.0`. Сборка выполняется компилятором MSVC на `windows-latest`, исполняемый файл собирается со статической библиотекой C++ (`/MT`).
