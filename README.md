# OneCManager

Программа (C++/WinAPI, один exe) для удалённого обнаружения, удаления и установки версий 1С:Предприятие.

## Возможности
- ввод имени удалённого ПК в окне программы;
- поиск всех установленных версий 1С (удалённый реестр, обе ветки Uninstall, x64/x86);
- список с галочками - «Удалить отмеченные» (msiexec /x {GUID} /qn);
- установка новых версий из сетевого пути, который вводится вручную (msi, exe или папка);
- способ запуска: стандартный (WMI + msiexec) или `pse.exe -r ps_1C` (переименованный psexec), либо авто (сначала стандартный, потом pse.exe).

## Требования
- запуск от учётной записи с правами администратора на целевом ПК (например, доменный админ);
- на целевом ПК доступны: RPC/WMI (DCOM), админ-ресурс `C$`, служба Remote Registry (программа попробует запустить её сама);
- `pse.exe` лежит рядом с программой или в PATH (нужен только для запасного способа).

## Установка
По умолчанию отмечено «Копировать дистрибутив на ПК»: папка с установщиком копируется через robocopy
в `C:\Windows\Temp\1C_Setup` на целевой ПК, установка идёт локально, потом папка удаляется.
Это обходит проблему «двойного перехода» (сетевая шара не открывается из удалённого процесса).
Если снять галочку, msiexec на ПК читает UNC-путь напрямую - у учётной записи/компьютера должен быть доступ к шаре.

Поле «Параметры» - ключи msiexec. По умолчанию стандартный набор для 1С (русский язык, толстый и тонкий клиент, конфигуратор);
подправьте под свою схему (компоненты, `TRANSFORMS`, `LANGUAGES`). Для `.exe` установщика поле используется как аргументы exe.

Коды результата: 0 - успех, 3010/1641 - успех, нужна перезагрузка. Лог msiexec на ПК: `C:\Windows\Temp\1c_ps.log`.

## Сборка релиза через GitHub (браузер или Android)
1. Создайте репозиторий на github.com.
2. Добавьте файл `main.cpp` в корень: **Add file → Create new file**, имя `main.cpp`, вставьте код, **Commit**.
3. Добавьте ещё один файл: имя вводится как `.github/workflows/build.yml` (слэши сами создадут папки), вставьте содержимое workflow, **Commit**.
4. Вкладка **Actions → Build and release → Run workflow**, введите версию (например `1.0.0`) и запустите
   (в приложении GitHub для Android: репозиторий → Actions → выбрать workflow → Run workflow).
5. Через 1-2 минуты в **Releases** появится релиз `v1.0.0` с файлом `OneCManager.exe`.

Альтернатива: создать релиз/тег вида `v1.0.0` - сборка запустится автоматически.
